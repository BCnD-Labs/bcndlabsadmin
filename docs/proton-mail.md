# Proton Mail in Blackwall

Blackwall connects to Proton Mail Bridge over IMAP and SMTP on **the server's loopback** (`127.0.0.1`, default ports `1143` and `1025`). It does not use a Proton account password. Settings → Connections stores Bridge's generated password in Blackwall's encrypted connection store. Mail is fetched on demand; it is not copied into the workspace. The Mail page reads the 100 most recently received messages per folder, sends plain-text mail, moves messages to Proton Trash, previews common attachments, and saves attachments directly to Nextcloud without replacing an existing file. Messages over 20 MB cannot be opened yet.

## Owner setup

1. In Proton Mail, add the domain under **Settings → All settings → Proton Mail → Domain names**. Add Proton's verification TXT record in Cloudflare DNS. Create the wanted domain address in Proton **before** switching MX records. Then replace Cloudflare Email Routing MX records with the MX records Proton gives you. Add Proton's SPF, three DKIM records, and DMARC; verify each in Proton. [Proton's Cloudflare walkthrough](https://proton.me/support/custom-domain-cloudflare) has the current values and order.
2. Add `COMPOSE_PROFILES=proton` and `BRIDGE_KEY_PASSPHRASE` to the Portainer stack environment (generate a new value with `openssl rand -hex 32`, then save it in your password manager) and redeploy the stack. The companion Bridge container installs an official Proton release pinned by checksum. It shares the app's network namespace and listens only on loopback; no mail ports are published. Its GPG/Pass keychain and encrypted cache persist in `bridge-data`. See [Bridge for Linux](https://proton.me/support/bridge-for-linux).
3. On Mikoshi, attach to the first-start Bridge CLI with `docker attach blackwall-bridge-1`. At the Bridge prompt enter `login`, sign in to Proton and complete 2FA, then enter `info` to see the **generated Bridge username and password**. Save those in your password manager. Enter `exit` to start Bridge in the background. Keep Bridge's connection mode at **STARTTLS**. [Bridge CLI guide](https://proton.me/support/bridge-cli-guide) lists the commands.
4. In Blackwall, add a **Proton Mail Bridge** connection in Settings → Connections. Enter Bridge's generated credentials, and optionally the domain address under **Send from**. Test the connection; it checks both IMAP and SMTP without sending a message. Do not enter your Proton account password in Blackwall.
5. Open **Mail**. Send a message to another address, reply from there with a small PDF or image attachment, read it, preview the attachment, and use **Save to Nextcloud**. Move a test message to Trash and confirm it appears in Proton's Trash folder. You can test with your existing Proton address before switching the domain's MX records.

The existing **Email (SMTP)** connection is for Blackwall notification delivery. It is separate from the Proton mailbox connection.
